# Patient list: component gaps

Where a prototype had to work around a Cadence component, or fall back on its own markup.

| Where in the prototype                          | What it needed                                                                                                                                                                                                                                                                                                                                                                                  | Component, and what to propose                                                                                                                                                                 |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Option A, every list                            | List and detail gives the list a narrow pane (16 to 22rem) beside a wide record. Option A's list is a table that needs the room, with the record as the narrower pane. The prototype overrides the grid columns.                                                                                                                                                                                | List and detail: a layout for a wide list, such as a `listSize` option, rather than a class override.                                                                                          |
| Option A, the acuity column                     | A Badge in a narrow table column broke a short word mid-word ("Mediu m"), because Badge wraps anywhere rather than clip. The prototype gives the column a minimum width.                                                                                                                                                                                                                        | Badge: keep short words whole in a table cell, as Table's own cells do (they wrap between words and never break a word).                                                                       |
| Option A, every row                             | A URN broke across lines at its hyphen, a misreading risk. The prototype keeps it on one line.                                                                                                                                                                                                                                                                                                  | Patient row (proposed) and Patient banner (proposed): identifiers never break.                                                                                                                 |
| Option A, the list's search                     | A search field with a search icon inside it, as shadcn's input group draws it. Cadence has no input group, so the prototype uses a plain Input with a placeholder and a label.                                                                                                                                                                                                                  | Input group (new): an Input with an icon or a button inside its edge, as shadcn's `input-group`.                                                                                               |
| Option A, every row                             | Rows the same height, for scanning. Since round 4, Data table's `rowLines` makes every row two or three lines tall, and `DataTableCellText` cuts text to the row's lines, but the whole text of a cut cell is still only in the patient's detail.                                                                                                                                               | Data table: a cell cut to its lines that shows its whole text on hover, focus or tap, so a cut-off cell is never the only place a value is shown.                                              |
| Option A, every row                             | The patient's name and URN must never be cut off or wrapped. Since round 4 the pinned Patient column is sized in `em` with Data table's `meta.width`, from the widest identity each list can hold, measured by a script at each density. The measuring is by hand: a longer name added to the data would run past the column's edge until it is measured again.                                 | Patient row (proposed): the identity lines take the width they need, and a list's pinned Patient column is sized from the longest identity on it.                                              |
| Option A, on a phone                            | The table's column sorting has no phone equivalent: the rows keep the view's order.                                                                                                                                                                                                                                                                                                             | Data table: a sort control for the phone layout, such as a "Sort by" select.                                                                                                                   |
| Option A, groups on a phone                     | Data table has no phone layout, so the prototype draws each group again as a heading over its cards, with Collapsible and Item, and splits the rows into groups itself.                                                                                                                                                                                                                         | Data table: a phone layout that keeps the groups, their counts and collapse, so the two layouts cannot disagree.                                                                               |
| Option A, every row (round 3)                   | The open row was marked only by its fill. Resolved in round 4: Data table marks a selected row with a bar at the start of its first cell, which stays in view in a pinned column.                                                                                                                                                                                                               | Done.                                                                                                                                                                                          |
| Option A, the Review view (round 3)             | The Review view has eleven columns, so at 1100px only Results and part of Vitals are in view beside the pinned Bed and Patient, and the rest scroll sideways. Three-line rows (round 4) narrow most columns, and show one more column at 1440px.                                                                                                                                                | Data table: a column menu per view (DataTableViewOptions exists), or a denser layout for review columns. A question for the maintainer.                                                        |
| Option A, incoming rows (round 3)               | A disabled control's reason is given by composing Tooltip, `aria-describedby` and a hidden paragraph in the prototype. No Cadence control takes a reason, and Base UI's Checkbox and Switch cannot stay focusable while disabled, so a keyboard cannot reach them to hear it.                                                                                                                   | A "disabled with a reason" pattern across Button, Checkbox, Switch and the editable cell: focusable while disabled, with the reason as its description. Deferred by the maintainer in round 4. |
| Option A, phone cards (round 3)                 | The phone's cards have no equivalent of the Data table's row click: only the summary button in each card opens the summary.                                                                                                                                                                                                                                                                     | Item: a card that opens on a press anywhere but its controls, as Data table's `onRowClick` does.                                                                                               |
| Option A, an open row at 1100px (round 4)       | With a patient open at 1100px, Bed, Patient and the last column (112px, wide enough for an incoming patient's Accept) covered more than two thirds of the table's box, so they stopped sticking. Resolved in round 5: Accept moved into the row's menu, the last column is one icon button (44px), and the pane narrows on a narrower screen, so the pinned columns cover 288px of a 479px box. | Done.                                                                                                                                                                                          |
| Option A, the comment thread (round 4)          | Editing or deleting a comment for 10 seconds, then only revoking it, is composed in the prototype: the countdown, holding the time open while editing, closing the toast when the time ends, the confirmation, and moving focus when Edit gives way to Revoke.                                                                                                                                  | Comment thread (new pattern): a thread with a box to add a comment and its author's actions, taking the window as a prop, so every product applies the same rule the same way.                 |
| Option A, editing in a three-line row (round 4) | `DataTableEditableCell` edits text in a one-line Input, so a working problem shown on three lines is edited on one.                                                                                                                                                                                                                                                                             | Data table: an editable cell that edits text over the row's lines, with Enter to save kept.                                                                                                    |
| Option A, removing a row (round 5)              | When a row is removed, its actions button goes with it, so the prototype moves focus to the next patient's name, or the list's heading, and back to the row's actions when the removal is cancelled. It finds them in the page by data attributes.                                                                                                                                              | Data table: a way to say which row takes focus when one leaves, so every list that removes a row moves focus the same way.                                                                     |
| Every screen, dark mode (round 5)               | The tokens switch colours on `data-mode`, but nothing sets the CSS `color-scheme`, so the browser's own parts stay light in dark mode: scrollbars where they are not overlaid, the search field's clear button, autofill and other native form parts.                                                                                                                                           | Tokens: set `color-scheme: light` or `dark` with the mode, and `light dark` when it follows the device. A library change, not patched in the prototype.                                        |
| Option A, the pane beside the list (round 5)    | To keep Bed, Patient and the actions pinned at 1100px, the prototype sets the pane's width to `clamp(20rem, 30vw, 26rem)` with a class override on List and detail.                                                                                                                                                                                                                             | List and detail: a layout for a wide list (round 1), with a detail pane that narrows on a narrower screen.                                                                                     |
| Option A, the pane's summary (round 6)          | Pairs of a term and its details that line up and stack on a narrow pane. The round 5 proposals drew a grid of `dt` and `dd` by hand.                                                                                                                                                                                                                                                            | Done: Description list.                                                                                                                                                                        |
| Option A, the pane's timeline (round 6)         | Everything that happened to a patient, newest first, each with its kind, who, when and what, holding a Comment with its actions.                                                                                                                                                                                                                                                                | Done: Timeline.                                                                                                                                                                                |
| Option A, the pane on a phone (round 6)         | A record opened from a scrolled list started part way down, with its way back under the sticky header.                                                                                                                                                                                                                                                                                          | Done: List and detail scrolls the record to its top.                                                                                                                                           |
| Option A, the pane's comments (round 6)         | The thread's rules (10 seconds to edit or delete, then revoke) now drive comments inside timeline items, through a provider in the prototype. Focus is moved by finding items by `data-comment` in the page.                                                                                                                                                                                    | Comment thread (new pattern, from round 4): take the window as a prop, and render each comment wherever the product lists it, such as in a Timeline item.                                      |
| Option A, moving through the rows (round 6)     | Previous and next need the rows in the order shown. The prototype moved the table's sorting and collapsed groups out of the table, and works the order out from the groups and the sorted rows itself.                                                                                                                                                                                          | Data table: give the rows in the order shown, groups included, so a pane beside the table can move through them.                                                                               |
| Option A, the identity in the pane (round 6)    | `PatientIdentity` at banner size kept its second line on one line, which ran past a 20rem pane. The prototype now wraps it between its parts.                                                                                                                                                                                                                                                   | Patient banner (proposed): wrap between parts and never inside one.                                                                                                                            |
