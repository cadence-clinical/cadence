The Observation table is a flowsheet. Each row is one series, such as heart rate, and each column is one round of observations, oldest on the left and newest on the right. It opens scrolled to the newest round.

The table makes no clinical judgement. It shows the band an observation schema gave each value, and the interpretation the source sent with it. It holds no threshold of its own.

## Use it for

- Reviewing a patient's observations over hours or days, round by round.
- The table beside an observation chart: the same values in rows, readable by a screen reader.

## Do not use it for

- A list of records to sort, filter or select. Use the [Data table](/docs/components/data-table).
- A single value, or the latest value of each observation.

## Where its data comes from

The table takes series that an observation schema has been applied to. From FHIR, that is two steps: read the Observations into series, then apply the schema.

```tsx
import { ObservationTable } from "@cadence-clinical/clinical";
import { applyObservationSchema } from "@cadence-clinical/core";
import { observationSeries } from "@cadence-clinical/fhir";

// schema: your observation schema, or one from a Region package.
const { series, issues } = observationSeries(bundle, { series: schema.series });

<ObservationTable
  label="Vital signs"
  series={applyObservationSchema(series, schema)}
  now={now}
  timeZone="Australia/Melbourne"
/>;
```

`observationSeries` checks every field it reads. Anything it cannot read is in `issues`, with the resource and the reason, and is never left out without a record.

Cadence ships no clinical schema. A schema's thresholds are yours to choose, or come from a Region package that cites its source.

## A round is one column

A set of vital signs is recorded over a minute or two, and each value carries its own time. The table puts readings taken within five minutes of a round's first reading in one column, headed by that first time. Change the window with `roundWindowMs`, or set it to 0 to give each time its own column.

When a round has two values for one series, such as a heart rate from a monitor and one counted by hand, the cell shows both.

## How a value shows its band

A value in a band other than the lowest has three signs besides its colour:

- a fill and an edge in the band's colour, from the fixed [severity scale](/docs/theming#severity-scale);
- the level's short label, in its own box before the value, such as **1**;
- bold figures.

A screen reader reads the level's words with the value: "108 beats/min, Synthetic level 1, up 16 since 22:00".

A value the schema could not judge has a dashed edge and a question mark, and says why:

| What                                   | Why it is not banded                                              |
| -------------------------------------- | ----------------------------------------------------------------- |
| A value in another unit than the bands | Its unit is shown in the cell. It is never compared across units. |
| A bound, such as less than 95          | The value could be in more than one band.                         |
| An answer the schema does not list     | The schema's answers are matched exactly, never guessed at.       |
| A value outside every band             | The schema's bands do not cover it.                               |

A value that was not recorded says "Not recorded" rather than leaving the cell empty.

## Show the change since the value before

Each number shows its change since the latest earlier value in the same row, as ▲ or ▼ and the amount, rounded to the precision the two values were written in. Two values taken at the same moment are not compared with each other.

## Times

Days are named "Today" and "Yesterday", and dates before that as a short date. Times use the 24 hour clock. Pass `now` and `timeZone`: the table never reads the clock or the device's time zone, so a page rendered on a server matches the browser.

## Accessibility

- Give the table a `label`. It names the scrolling region and the table for a screen reader.
- The scrolling region takes focus, so a keyboard can scroll it.
- Each value's band, change and source interpretation are read out in words, and shown on hover.

## Props

| Prop            | Type                                | Default   |
| --------------- | ----------------------------------- | --------- |
| `series`        | `InterpretedSeries[]`               | Required  |
| `label`         | `string`                            | Required  |
| `now`           | `string \| number`                  | Required  |
| `timeZone`      | `string`                            | Required  |
| `locale`        | `string`                            | `"en-AU"` |
| `hourCycle`     | `"h23" \| "h12"`                    | `"h23"`   |
| `roundWindowMs` | `number`                            | `300000`  |
| `messages`      | `Partial<ObservationTableMessages>` | en-AU     |

`messages` replaces any of the words the table shows or reads out.

## Install

The clinical components are not on npm yet.

```tsx
import { ObservationTable } from "@cadence-clinical/clinical";
```

Import its stylesheet after the ui stylesheet, so Tailwind finds its classes:

```css
@import "@cadence-clinical/ui/styles.css";
@import "@cadence-clinical/clinical/styles.css";
```

From the registry, `shadcn add @cadence/observation-table` installs it beside your Table, and adds `@cadence-clinical/core`.
